# 사이트 설계도(PRD) — 데일리 매출 대시보드 (이름 미정)

작성일: 2026-11-15 · 이 문서는 사이트를 고칠 때마다 다시 보는 기준이다.

## 1. 한 줄 정의
온라인 쇼핑몰 여러 곳의 매출 CSV를 올리면 쌓아 두고, 나와 직원이 매일 하루 매출을 한눈에 보는 비공개 대시보드.

## 2. 보는 사람
- 누가: 나(사장) + 직원 몇 명
- 언제·어디서: (미정) — 매일 확인. 폰과 PC 둘 다에서 보기 좋게 만든다

## 3. 열자마자 궁금한 것
1. 오늘(어제) 매출 — 전날·지난주 같은 요일 대비
2. 주문 수 · 객단가(주문 1건당 평균 금액)
3. 잘 팔린 상품
4. 이달 누적 매출 · 목표 대비 몇 %

## 4. 숫자를 믿게 할 근거
- 숫자는 올린 CSV에서만 계산한다. 지어내거나 예측하지 않는다
- 화면에 "마지막으로 올린 파일 · 날짜 범위"를 보여 줘서 어디까지 반영됐는지 알 수 있게 한다
- 데이터가 없는 날은 0이 아니라 "데이터 없음"으로 보여 준다

## 5. 누르게 할 버튼 하나
- 버튼 이름: CSV 올리기
- 누르면: 파일 고르기 → 미리보기(몇 건, 날짜 범위, 쇼핑몰) → 저장 → 대시보드 숫자 새로고침
- 같은 주문을 두 번 올려도 두 번 세지 않는다(쇼핑몰 + 주문번호로 중복 확인)

## 6. 페이지 구성 (위에서 아래로)
1. 잠금 화면 — 공용 비밀번호 입력칸 하나
2. 대시보드 첫 화면 — 날짜 고르기 + 핵심 숫자 4개(3번 목록)
3. 최근 30일 일별 매출 추이
4. 잘 팔린 상품 순위
5. 쇼핑몰별 매출 나눠 보기
6. CSV 올리기 · 올린 기록

## 7. 저장할 데이터 (CSV에서 꼭 필요한 칸만)
- 주문 날짜, 쇼핑몰 이름, 주문번호, 상품명, 수량, 결제 금액
- **구매자 이름·전화번호·주소는 저장하지 않는다**(매출 계산에 필요 없음, 개인정보)
- 금액 기준(결제 금액 / 정산 금액, 취소·환불 빼는 방법): (미정 — 실제 CSV를 보고 정한다)

## 8. 정확해야 하는 사실 (사용자가 말한 그대로)
- 판매 채널: 여러 쇼핑몰이 섞여 있음 — 쇼핑몰 이름: (미정)
- CSV 칸 이름·모양: (미정 — 쇼핑몰마다 다름. 쇼핑몰마다 샘플 파일 하나씩 필요)
- 이달 매출 목표 금액: (미정 — 대시보드에서 직접 입력하게 한다)
- 보는 사람 수: 나 + 직원 몇 명 (정확한 수: 미정)

## 9. 이번에 넣지 않을 것
- 사람마다 로그인(이메일 계정) — 이번엔 공용 비밀번호 하나
- 쇼핑몰과 자동 연동(API) — 이번엔 CSV를 손으로 올린다
- 매출 예측, 알림 메일·카톡
- 광고비·원가·순이익 계산
- 구매자(고객) 정보 분석

## 10. 첫 화면 한 문장 후보
1. 어제 매출, 열자마자 한눈에.
2. 쇼핑몰 여러 곳의 하루 매출을 한 화면에서.
3. CSV 하나 올리면 오늘의 숫자가 정리돼요.

## 11. 다음에 할 것
- 사람마다 로그인 + 누가 언제 올렸는지 기록
- 쇼핑몰 자동 연동(API)으로 CSV 올리기 없애기
- 목표 대비 늦어지면 알려 주기
- 월별·연도별 비교, CSV 내려받기

## 12. 만드는 방법 (클로드가 끝까지 만들 때 기준)
- 분위기: 깔끔한 — 숫자가 한눈에 들어오는 차분하고 단정한 화면 · 참고 디자인: 없음 — 클로드가 정함
- 잠금: 공용 비밀번호 하나(`ADMIN_PASSWORD` 환경변수). 화면·API 모두 비밀번호 없이는 숫자를 주지 않는다. 검색 노출 금지(noindex)
- 데이터 저장: 예 → Supabase(`sales` 표, RLS 켜고 정책 없음 — 서버 `/api`만 접근). leaderpl-admin 스킬의 원칙을 따른다
- CSV 읽기: 쇼핑몰마다 칸 이름을 맞춰 주는 규칙을 둔다. 처음 보는 모양이면 저장하지 않고 "어느 칸이 날짜·금액인지" 고르게 한다
- 회원가입: 이번엔 아니요
- 배포: GitHub 저장소 + Vercel — 저장소 이름과 공개/비공개는 만들기 전에 먼저 정한다(매출 대시보드라 비공개 권장)

## 13. 만드는 순서 (클로드가 처음부터 끝까지 한 번에)
1. 쇼핑몰별 샘플 CSV를 받아 칸 이름을 확인하고, 저장할 칸(7번)에 맞추는 규칙을 정한다
2. 스타일(색·글꼴)을 "깔끔한"에 맞게 정하고 잠금 화면 → 대시보드 첫 화면부터 만든다
3. GitHub 저장소에 올리고 Vercel로 배포해 내 주소를 만든다
4. Supabase 표 → CSV 올리기 `/api` → 대시보드 숫자 계산 `/api`까지 연결한다
5. 다 만든 뒤 한 번에 보고: 내 사이트 주소 · 확인 방법 · 사용자가 할 일
- 사용자가 직접 할 일(이때만 멈춤): 로그인(GitHub·Vercel·Supabase), 결제, 샘플 CSV 준비, 관리자 비밀번호 확인
